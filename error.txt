2. VIỆC KẾ TIẾP — CẦN MÁY CÓ MẠNG, LÀM THEO ĐÚNG THỨ TỰ
===============================================================================

Bước 1. Lấy code
  cd ~/scanner && git pull && source .venv/bin/activate

Bước 2. Kiểm tra chạy được
  python -m pytest -q
  python bars.py && python structure.py && python setups.py && python backtest.py

Bước 3. Dựng kho nến — LẦN ĐẦU, CHẠY TRONG tmux (mất 30-60 phút)
  tmux new -s bars
  python bars.py --sync --full
  python bars.py --info          # bao nhiêu mã, bao nhiêu nến, ngày mới nhất
  (thoát tmux: Ctrl-b rồi d · vào lại: tmux attach -t bars)
  Chạy thử trước cho nhanh nếu muốn: python bars.py --sync --full --limit 200

Bước 4. Đối chiếu trước khi tin — QUAN TRỌNG, ĐỪNG BỎ
  cp state/baseline.db /tmp/copy.db
  rồi so adv20/prev_close giữa `base` hiện tại và bản --from-bars trên /tmp/copy.db.
  Lệch quá vài phần trăm = kho nến thiếu ngày. Mọi thứ dựa trên baseline sẽ sai
  ÂM THẦM, không có gì báo lỗi.
  CHƯA đối chiếu xong thì CHƯA đổi cron.

Bước 5. Dựng struct + candidates
  python structure.py --build       # in luôn danh sách "sắp vượt pivot"
  python structure.py --show NVDA
  python setups.py --build          # in bảng LÝ DO BỊ LOẠI
  python setups.py --show BO --n 40

  Đọc bảng lý do bị loại: "khong co nen tich luy" chiếm gần hết là BÌNH THƯỜNG
  (phần lớn thị trường không ở nền). "con xa pivot" chiếm gần hết = thị trường
  vừa rơi mạnh, và BO đúng ra nên im lặng.

Bước 6. BACKTEST — đây là việc quan trọng nhất, làm trước khi tin ngưỡng nào
  python backtest.py --run --limit 300
  python backtest.py --run --by base_len
  python backtest.py --run --by base_depth
  python backtest.py --run --by rs_pct
  python backtest.py --run --by rvol
  python backtest.py --run --setup RV --rv-no-fund

  Cách đọc, bốn điều:
   - So med10 với dòng `ngau nhien`. Không hơn = setup không có lợi thế gì.
     55% thắng không nghĩa lý gì nếu vào mù cũng thắng 54%.
   - Cột MAE quan trọng ngang med. MAE trung vị -12% thì dù lãi 12% cũng không
     giao dịch được: đã cắt lỗ trước khi nó lãi.
   - Backtest vào lệnh ở GIÁ ĐÓNG CỬA, còn bot alert GIỮA phiên -> thật sẽ xấu hơn.
   - Kho nến chỉ còn mã ĐANG SỐNG (survivorship bias) -> số đẹp hơn thực tế.
     RV lệch nặng nhất, đừng so win% của RV và BO như hai số cùng thang.

  Sau khi đọc: chỉnh dict BO ở đầu setups.py BẰNG SỐ, không bằng cảm giác.
  Sửa một chỗ đó là cả bot lẫn backtest đổi theo (có test khoá việc này).

Bước 7. Chỉ khi bước 4 và 6 đã ổn thì mới đổi cron (thay dòng prep.py cũ)
  CRON_TZ=America/New_York
  0 8 * * 1-5  cd /home/ubuntu/scanner && .venv/bin/python bars.py --sync >> state/prep.log 2>&1 && .venv/bin/python prep.py --from-bars >> state/prep.log 2>&1 && .venv/bin/python structure.py --build >> state/prep.log 2>&1 && .venv/bin/python setups.py --build >> state/prep.log 2>&1

  Đổi được thì bỏ hẳn một lượt tải yfinance: prep.py hiện tải 4 tháng nến cho
  ~5000 mã rồi ném đi, chỉ giữ 3 con số.

9.3  fundamentals.py + bảng `fund`  — CHẶN RV
     RV hiện dựng được danh sách theo dõi nhưng KHÔNG alert, vì fund_ok=None
     ("chưa biết") không bao giờ được coi là đạt. Đó là cố ý.
     Nguồn: SEC XBRL frames API
       data.sec.gov/api/xbrl/frames/us-gaap/<concept>/USD/CY2025Q2.json
     Một request trả về cả thị trường cho một chỉ tiêu một quý -> phủ 5000 mã
     bằng ~40 request/tuần. SEC_UA đã có trong .env.
     Điểm cơ bản xây quanh SỐNG SÓT + KHÔNG PHA LOÃNG, không quanh P/E:
     tăng trưởng số lượng cổ phiếu YoY (>25%/năm là cờ đỏ, quan trọng hơn mọi
     chỉ số lợi nhuận với small-cap), tiền/tốc độ đốt tiền >= 6 quý, nợ/vốn chủ,
     lịch sử S-1/S-3/424B5/ATM 12 tháng.
     Frames phủ KHÔNG đầy đủ (cùng khái niệm có nhiều tag XBRL) -> mã thiếu số
     liệu phải là "chưa biết" và bị loại khỏi RV.
